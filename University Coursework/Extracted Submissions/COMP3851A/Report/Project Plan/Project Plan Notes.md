## Project description ##
May change minds, maybe slightly, get given exact specification of what to be done, full description next week.

* Title – something catchy
* Summary - __All__
    * 100-150 words
    * includes aims, outcomes, significance and social and or economic benefits.
    * Best to be written last.
    * Should use language for public/press release.
    * Can be used as marketing tool
* Aims – what is object of work __Evan__
    * Keep aims clear and succinct.
    * Dot points can work. (Yeah no na Yeah)
    * Ask is it genuinely feasible in the timeframe available?
    * Are the teams skills adequate?
    *  No real number for aims, depends on complexity of project and available time.
    * Don’t have 1 big aim, have smaller aims(Divide and conquer)
* Background – background as to why we chose project __Jordan / Mat__
    * Let reader know context of problem your team is addressing.
    * Use subheadings to identify themes and or other issues. * How do people address that problem now?
    * Are there any unresolved issues? Why are they unresolved or unsatisfactory? How do you think you will overcome the problem/issue?
* Approach – which approach to use to achieve aims, deliverables (can match with aims). __Mat__
    * Describe design and methods to be used.
    * Explain how these are appropriate and how they integrate with the aims of the project.
    * Not only describe, critically analyse the approaches (how are these approaches appropriate), how they integrate with project description
* Timetable – this is a measure of the projects feasibility and helps clarifying who is doing what __Jordan__
    * Link phases of the work plan / approach with the anticipated timeline
    * List milestones (new row in timetable)
        * Prototypes, tests, validation, etc.
    * Build in any ethics clearances requires ( if applicable)
    * Gantt chart, same information from approaches into timetable form.
    * Explain to alex or in report the justification for time allocation (testing, etc.)
* Expected outcomes – related to aims but more specific, e.g. deliver prototype. __Evan__
    * Complexity involved, link to the aims – what will be anticipated results be of what you plan to do
    * Be realistic as you will be judged on these outcomes, outcomes must be in line with 3rd year level project and require knowledge at that level
* References – list of references used throughout project
    * Journal papers, websites, report, use standard for citing regerences e.g. Harvard style (or just let latex handle it)
